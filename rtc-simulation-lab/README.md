# Independent SYNTHETIC RTC simulation laboratory

This directory is independent of the active backend, database, migrations, model registry and NLP training datasets. It imports only its own package and Python's standard library at runtime. It creates no real live positions and contains no official APSRTC timetable, fare or operational information. Every generated record is SYNTHETIC. Category and operator names indicate fictional service styles only.

Python 3.12+ is required. Run commands from this directory. A separate `.venv` was used for verification; nothing is installed into a production environment.

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-test.lock
.\.venv\Scripts\python -m rtc_simulation generate
.\.venv\Scripts\python -m rtc_simulation validate
.\.venv\Scripts\python -m rtc_simulation benchmark
.\.venv\Scripts\python -m rtc_simulation replay
.\.venv\Scripts\python -m rtc_simulation report
.\.venv\Scripts\python -m pytest -q
```

The five CLI commands run completely offline without installing any packages. Test dependencies can be provisioned beforehand on a connected machine with the same Python/platform:

```powershell
python -m pip download -r requirements-test.lock -d wheelhouse
# Copy this directory, including wheelhouse, to the offline machine.
.\.venv\Scripts\python -m pip install --no-index --find-links wheelhouse -r requirements-test.lock
```

The wheelhouse is not bundled. The source package runs directly from this directory without an editable install or build backend download. Default seed is 73129; all timestamps include +05:30. Generated bytes and manifest checksums are reproducible; measured report timings are intentionally variable.

```powershell
.\.venv\Scripts\python -m rtc_simulation benchmark --category C
.\.venv\Scripts\python -m rtc_simulation replay --now 2026-11-08T08:03:00+05:30
.\.venv\Scripts\python -m rtc_simulation generate --root alternate-fixtures --seed 42 --config docs/example-config.json
.\.venv\Scripts\python -m rtc_simulation benchmark --adapter my_adapter:respond
.\.venv\Scripts\python -m rtc_simulation benchmark --mode nlp --adapter my_adapter:respond
```

`--root` controls artifact destination/source. `--category A` through `J` filters scenarios. A benchmark `--now` override changes execution time but retains the original gold expectations, so differences can intentionally fail. Benchmark exit codes: 0 all pass, 1 comparison/validation failure, 2 invalid inputs. Structured per-case failures and exceptions are in `reports/benchmark.functional.json` or `benchmark.nlp.json`.

Artifacts: versioned JSON network/events; JSONL functional scenarios and English evaluation questions; import-ready UTF-8 CSV exports of every collection (nested values encoded as JSON); SHA-256 manifest. See `docs/format.md`, `docs/adapter.md` and `docs/business-rules.md` before integration.

The 540 scenarios comprise 54 business-case patterns with ten parameter sets. They are not 540 independently discovered requirements. Gold results are literal expected itineraries or simple separately authored fare arithmetic; generation never calls the reference calculator. Small fixtures use symbolic city-qualified stops so each case is understandable without the large network. The large network is for scale/data quality, not a claim of geographically calibrated route realism. English questions include short/Indian English, ambiguity, correction, multi-intent and context-dependent forms with explicit conversation context. This evaluation set must never be copied into training, threshold tuning or Phase 2 data.

The default benchmark checks the standalone reference engine against authored gold. This is not a backend integration score or an NLP accuracy measurement. NLP mode requires an external adapter and fails clearly without one. Reports list remaining coverage limits. No production schema mapping is assumed and no branch is merged.
