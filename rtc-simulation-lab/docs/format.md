# Format contract 1.0 / fixture 1.0.0

Every top-level document and every JSONL/CSV record carries schema_version, fixture_version, random_seed and source_label. Nested network records inherit document versions and each carries SYNTHETIC provenance. JSON null is unknown, not zero. CSV nested dictionaries/lists and null are JSON encoded; scalar columns are ordinary CSV. Money is decimal text. Times are timezone-aware ISO 8601; dates are YYYY-MM-DD. Weekdays are Monday=0 through Sunday=6.

network.v1.json contains cities, stations (city_id), routes (ordered station IDs), trips (route_id, operator, category, ordered absolute stops, weekly calendar and date exceptions, cancellation, delay, platform, amenities, seat snapshot and optional fare override) and fares (route_id, effective dates, distance rate). Four absolute occurrences per route are generated on the anchor operating date; this is not an infinite recurring timetable expansion. Overnight stops roll into the next date. Route direction is explicit and no reverse service is inferred. Distances in fare gold fixtures are explicit inputs; the synthetic route generator does not imply geographic distances.

functional.v1.jsonl has id, category A-J, description, frozen_now, embedded fixture, structured enquiry, expected_result, expected_warnings, data_provenance, business_rule and coverage tags. Embedded fixture references are independent from network IDs. English rows have id, scenario_id, question, style, conversation_context, expected_intent, entity_constraints, expected_database_query, final_factual_result and evaluation_only=true.

Event rows contain id, at, kind, service_id, payload and metadata. Replay sorts by absolute timestamp then event ID; duplicate IDs fail, unknown trip IDs fail and future events are excluded. Delays replace the current delay value; platform/seat updates replace snapshots; arrived/departed set operational_status. Diversions are recorded as notices; no unreviewed route topology is invented. Replay returns copied state plus the applied event log and live_positions=false. To resume, replay the complete log against the original snapshot; this is not an incremental exactly-once consumer.

manifest.v1.json hashes every generated fixture, scenario and benchmark file (including CSV) with SHA-256. Reports and source code are not included. Report JSON contains counts, per-axis coverage, validation findings, benchmark totals and explicit missing coverage. Generation overwrites only lab artifacts at the selected root; use a dedicated root. Reports should be regenerated after generation and benchmark execution.
