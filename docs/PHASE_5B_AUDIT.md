# Phase 5B operational gap matrix

Request: `phase5b-request.md`. Existing implementation was inspected rather than assumed complete. No new trip-status, event-history or platform table was created.

1. **Audit:** Existing Trip, TripStopTime, DelayEvent, StatusHistory, PlatformAssignment, Disruption, Alert, DataSource, Audit, local users/grants and enquiry engines were present. Dispatcher state validation, station scopes, concurrency/idempotency, publication review for notices and live transport were missing. Extended those modules.
2. **Control center:** `/admin/operations` provides station/operator/origin-service-date selection, arrivals, departures, delayed/cancelled trips, platforms, disruptions and event history, actual database counts, searchable/sortable/paginated board and text status indicators.
3. **Board:** `/board` uses the same public read-only board API as the console. Scheduled/estimated/actual timestamps, platform kind, freshness, last update and DEMO provenance remain separate. WebSocket invalidations, polling and manual refresh work locally.
4. **State machine:** `TripOperationalStateMachine` separates trip lifecycle, per-stop phase and delay. It validates chronology, forward stop order, departure/arrival ordering, terminal/inactive states, ready/boarding and destination completion. Supervisor corrections append events and deactivate superseded observation projections.
5. **Actions:** Boarding, ready, arrival, departure, transit, completion, revised arrival/departure ETA, delay/reason, platform change, cancellation, suspension, reinstatement request/approval, notice request/publication, announcement request/publication and correction are real authenticated database operations.
6. **Platforms:** Existing assignments hold PLANNED (legacy unverified), DISPATCHER_CONFIRMED or explicitly observed ACTUAL_BOARDING distinctions. Overlapping confirmed assignments are rejected; reassignment preserves history. Physical occupancy is UNKNOWN when no occupancy observation exists.
7. **ETA:** Manual estimates carry source, verification/effective/expiry times and reason. No historical-average ETA or numeric confidence is invented. Stale estimates are hidden from current ETA fields and labelled stale; recording an actual event cannot revive an expired estimate.
8. **Cancellation:** Existing `Trip.status='cancelled'` drives planner exclusion, with SUSPENDED kept as a separate operational lifecycle. Reinstatement needs a different supervisor, current version, valid service/timetable and conflict-free platform references.
9. **Disruptions:** Eight types, severity, reason/description, affected station/service/route/trip IDs, start/end, source and publishing user are supported. Dispatcher requests remain private; different-supervisor publication inserts existing verified Disruption rows. No remote weather/traffic inference.
10. **Event history:** Existing Audit is extended with station/source/occurred time and unique idempotency key. Previous state, new state/details, version, reason and actor are transactional with projections. ORM update/delete of operational audit events is blocked. Corrections append history.
11. **Realtime:** Same-origin local WebSocket invalidations use monotonic ledger revisions without Redis. Clients reject duplicate/older revisions, reconnect with backoff, detect missing heartbeats, refetch authoritative state after reconnect and retain polling/manual fallback.
12. **Passenger integration:** Existing enquiry/NLP paths consume the same platform, delay and stop observations. Delay answers now include verified revised departure and confirmed platform. Actual departure requires a recorded observation; no clock-based inference. The missing English “delayed” rule was fixed after live acceptance exposed it.
13. **Planner:** Existing route planning excludes cancelled/suspended trips, uses verified revised stop times and recomputes connection feasibility. No second planner was introduced; stale/incomplete data preserves existing scheduled/unknown qualifications.
14. **Announcements:** Local English JSON templates support delay, platform, boarding, arrival, departure, cancellation and reinstatement, with an unknown-safe alternative. Preview/request and separate supervisor publication use existing Alert rows. Changed facts invalidate a pending announcement preview.
15. **Authorization:** Existing local capabilities support operations viewer, dispatcher, station supervisor and operator administrator, plus existing system root. Operator/station grant pairs are checked at mutation/history/detail endpoints. A viewer cannot mutate; ordinary master editors are not dispatchers.
16. **REST:** `/api/v1/operations/board`, `/trips`, `/trips/{id}`, `/trips/{id}/events`, `/events`, `/platforms`, `/disruptions`, `/announcements`, `/quality` and `/stream` reuse one event command route rather than parallel action representations. Requests and board/event response envelopes use Pydantic.
17. **Quality:** Transition, time, reference, provenance, scope, idempotency and version checks reject unsafe updates transactionally. Quality inspection identifies stale estimates and invalid legacy actual-time ordering. Platform console reports recorded conflicts; corrections preserve the original record.
18. **Offline:** Local React bundle, FastAPI, SQLite/PostgreSQL, authentication, JSON templates, audit and WebSocket transport. Browser tests reject non-local requests; test backends block external socket connections before application import/startup.
19. **Tests:** Real SQLite/PostgreSQL dispatcher tests and production-bundle Playwright tests cover the requested categories, including idempotency, concurrency, intermediate stops, station/operator scope, announcements/notices, stale estimates, WebSocket/reconnect and passenger NLP. Exact executed results are in the report.
20. **Acceptance:** Both isolated strict-mode browser workflow and main-app DEMO API/NLP acceptance execute delay, revised departure, platform reassignment, no false departure, actual departure and actor/source/timestamp audit. Main-app proof is `phase5b-live-acceptance.json`. The stored demonstration station is named Vijayawada; no authoritative physical PNBS mapping is claimed.
21. **Deliverables:** Working operations console/board, validated event engine, platform/ETA/cancellation/reinstatement, reviewed disruptions/announcements, local live transport, integrations, tests, migration preservation evidence and setup/report documentation. No Phase 5C or voice work.

Schema: incremental 0015 extends existing Trip/Audit/Disruption/AdminUserRole tables; 0016 adds assignment kind to existing PlatformAssignment. Applied migrations 0001–0015 were preserved when the extra boarding distinction required 0016. Live old-column preservation is recorded separately from subsequent explicit DEMO acceptance writes.
